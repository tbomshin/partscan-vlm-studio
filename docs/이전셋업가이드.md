# AMD Radeon RX Vega 64 HBM2 풀가동 및 Vulkan 런타임 셋업 가이드
> **문서 목적**: 본 가이드는 데스크탑(AMD Ryzen 7 5800X3D + Radeon RX Vega 64 8GB HBM2) 환경에서 **484 GB/s에 달하는 HBM2 초고속 메모리 대역폭을 100% 손실 없이 끌어내어 `Jeff-Gemma4-E2B` 로컬 VLM을 0.2~0.3초 만에 구동**하기 위한 하드웨어 아키텍처 및 런타임 설정 가이드입니다.

---

## 1. 하드웨어 가속 아키텍처 (Vulkan + HBM2 484 GB/s Engine Graph)

AMD Vega 64는 NVIDIA CUDA가 작동하지 않으므로, 윈도우에서 HBM2의 2048비트 광대역 버스를 쓰려면 반드시 **Vulkan API**를 통해 GPU 하드웨어와 직결해야 합니다.

```mermaid
graph TD
    subgraph SYSTEM_RAM [시스템 RAM 영역 (DDR4 ~40 GB/s - 병목 유발)]
        DDR[DDR4 32GB 시스템 메모리]
        CPU[AMD Ryzen 7 5800X3D 8C/16T<br/>96MB 3D V-Cache]
    end

    subgraph PCIE_BUS [PCIe 3.0 x16 버스 (15.7 GB/s)]
        BUS[초당 15.7 GB/s 전송 대역폭]
    end

    subgraph VEGA64_HARDWARE [AMD Radeon RX Vega 64 하드웨어 영역]
        subgraph VRAM_HBM2 [초고속 8GB HBM2 스토리지 (484 GB/s 대역폭!)]
            WEIGHTS["[Jeff-Gemma4-E2B GGUF]<br/>모든 레이어 100% 상주 (-ngl 99)<br/>점유용량: 약 2.2 GB / 8.0 GB"]
        end

        subgraph COMPUTE_UNITS [64 Next-Gen Compute Units (4,096 Stream Processors)]
            VULKAN_CORE["Vulkan Compute Engine<br/>(ggml-vulkan.dll / DirectML)"]
        end

        WEIGHTS <===>|2048-bit HBM2 버스: 484 GB/s 극한의 전송속도| VULKAN_CORE
    end

    SYSTEM_RAM -.->|초기 모델 로딩 1회만 전송 (약 1.5초)| PCIE_BUS
    PCIE_BUS -.->|VRAM으로 100% 오프로드 완료 후 통신 단절| VEGA64_HARDWARE

    APP[FastAPI / Python 검수 앱] <-->|로컬 REST API 0.001s| VULKAN_CORE
```

### 아키텍처 핵심: "PCIe/DDR4 병목 완전 차단"
* 모델의 모든 신경망 레이어가 HBM2 VRAM 안으로 100% 들어가지 않고 단 1개라도 시스템 RAM(DDR4)에 걸쳐있으면, 초당 484 GB/s의 속도가 PCIe 버스 속도(15.7 GB/s)로 곤두박질칩니다.
* 따라서 **`-ngl 99` (모든 레이어 GPU 오프로드)** 옵션을 통해 **오직 484 GB/s 속도의 HBM2 메모리 내부에서만 텐서 연산이 완결**되도록 강제해야 합니다.

## 2. 런타임 셋업 3단계

### 1단계: llama.cpp Vulkan 바이너리 다운로드
1. [llama.cpp 공식 릴리즈 페이지](https://github.com/ggerganov/llama.cpp/releases)로 이동합니다.
2. 최신 릴리즈 목록 중 **`llama-bXXXX-bin-win-vulkan-x64.zip`** 파일을 다운로드합니다.
3. 압축을 풀면 폴더 내에 **`ggml-vulkan.dll`**과 **`llama-server.exe`**가 들어있는지 확인합니다.

*(대안: `Ollama`를 설치하는 경우, AMD 드라이버가 최신이면 내부적으로 DirectML/Vulkan 드라이버를 자동 로드합니다)*

### 2단계: HBM2 100% 상주 서버 실행 명령

```bash
# Vulkan 백엔드로 Jeff-Gemma4-E2B 2B 모델 기동
llama-server.exe ^
  -m models/jeff-gemma4-e2b.Q4_K_M.gguf ^
  --port 11434 ^
  -ngl 99 ^
  -c 2048 ^
  -b 512
```

* **파라미터 설명**:
  * **`-ngl 99` (필수)**: 99개 레이어를 GPU에 할당하여 모델 전체를 8GB HBM2 VRAM에 100% 상주.
  * **`-c 2048`**: 컨텍스트 창 크기 (부품 라벨 분석 시 2048 토큰이면 충분).
  * **`--port 11434`**: 본 프로젝트의 `vlm_engine.py`가 기본 통신하는 포트.

## 3. HBM2 풀가동 검증 방법 (작업 관리자 확인)

모델에 이미지 분석을 요청했을 때, Windows 작업 관리자(`Ctrl + Shift + Esc`)의 **[성능] ➔ [GPU (AMD Radeon RX Vega 64)]** 탭을 열어 아래 3가지를 확인합니다:

```text
[작업 관리자 성능 모니터링 체크리스트]
1. 전용 GPU 메모리 (Dedicated GPU Memory)
   └─ [확인]: 8.0 GB 중 '2.0 GB ~ 2.5 GB'가 채워져 있어야 함.
   └─ [주의]: '공유 GPU 메모리(Shared GPU Memory)'는 반드시 0 MB 근처여야 함!

2. GPU 엔진 그래프 (Engine Graphs)
   └─ [확인]: 우측 4개 그래프 중 하나를 'Compute_0' 또는 'Compute_1' 또는 'Vulkan'으로 변경.
   └─ [확인]: 파이프라인에서 이미지 판독 요청이 들어갈 때 해당 Compute 그래프가
              순간 80% ~ 100%로 솟구치면 HBM2 하드웨어 연산 100% 정상 작동!

3. 초당 생성 토큰 속도 (Inference Speed)
   └─ [확인]: JSON 생성 속도가 초당 80 ~ 110 토큰(t/s)으로 쏟아지며,
              이미지 1장당 총 소요 시간이 0.25초 ~ 0.35초 내로 완료되는지 확인.
```

## 4. Vega 64 전용 튜닝 꿀팁 (발열 제거 & 최대 클럭 유지)

Vega 64는 팩토리 기본 전압이 과도하게 높게 세팅되어 있어 장시간 배치 처리 시 스로틀링(Throttling)으로 HBM2 클럭이 떨어질 수 있습니다.

* **AMD Software: Adrenalin Edition 설정**:
  1. **성능 ➔ 튜닝** 메뉴로 이동합니다.
  2. 튜닝 제어를 **수동(Manual)**으로 설정하고 **GPU 튜닝** 및 **VRAM 튜닝**을 활성화합니다.
  3. **전압 언더볼팅**: P6, P7 단계 전압을 `-50mV ~ -75mV` (예: 1150mV ➔ 1075mV) 낮춥니다.
  4. **HBM2 메모리 클럭**: 945MHz를 유지하거나 살짝 1000MHz로 고정합니다.
  5. **전력 제한(Power Limit)**: `+15%`로 설정.
* **효과**: 소비 전력과 발열이 50W 이상 급감하면서 팬 소음이 줄어들고, **HBM2 메모리가 최대 대역폭(484 GB/s)을 스로틀링 없이 일정하게 유지**하여 1,652건 대량 검수 시에도 속도 저하가 전혀 발생하지 않습니다.
